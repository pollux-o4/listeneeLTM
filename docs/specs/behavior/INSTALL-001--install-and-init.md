# INSTALL-001 · 설치와 첫 설정

- 범위: Linux x64, macOS arm64, Windows x64. npm 설치와 단독 실행 파일 설치. 선택 이유: ADR-0009.
- 사전 조건: npm 경로는 Node·pnpm, 단독 경로는 OS 기본 셸과 브라우저. 공개 설치에는 해당 버전의 릴리스·npm 패키지가 게시되어 있어야 한다.
- 입력: `pnpm add -D listenee-ltm`, 또는 OS용 설치 스크립트·단독 실행 파일. 프로젝트에서 `ltm init`, `ltm ui`를 실행한다. 로컬 npm 명령은 `pnpm exec ltm`으로 호출한다.
- 기대 동작
  - npm은 해당 OS·CPU의 실행 파일을 설치한다. 설치 후 별도 빌드·사후 설치 스크립트 승인 없이 실행한다.
  - 단독 파일은 Node·Rust 없이 UI와 CLI를 제공한다. 설치 스크립트는 동일 버전 체크섬을 검증한 뒤 실행 파일을 교체한다.
  - `init`은 `.ltm/briefs`·세부 안내를 만들고 프로젝트 `AGENTS.md`에 포인터만 추가한다. 기존 `CLAUDE.md`도 안내하되 `@AGENTS.md`를 읽으면 생략한다.
  - 기존 안내·사용자 파일과 등록된 블록은 보존한다. 반복·동시 초기화로 안내가 중복되거나 내용이 유실되지 않는다. `.ltm/.gitignore`의 사용자 규칙을 보존하고 `history/`를 제외한다.
  - 공개 npm 패키지는 프로젝트 LICENSE와 의존성 고지 원문을 포함한다. 단독 실행 파일은 `ltm licenses`로 의존성 고지를 출력하며 설치된 프로젝트 데이터에 접근하지 않는다.
  - AI 안내는 전역 실행 파일과 프로젝트 로컬 실행 파일의 호출 방법을 설명한다.
  - `ui`는 루프백에 바인드한 뒤 기본 브라우저를 연다. `--no-open`은 브라우저 실행을 생략한다. 브라우저 실행 실패 시 서버와 URL 안내는 유지한다.
- 실패 복구: 미지원 플랫폼·누락된 선택 의존성·다운로드/체크섬 실패는 원인과 다음 행동을 알린다. 설치 실패 시 기존 실행 파일을 보존한다. 사용 중인 Windows 실행 파일 교체 실패는 서버 종료 후 재실행한다.
- 완료 기준: 빈 프로젝트에서 설치 → 초기화 두 번 → 지시서 생성·편집 → UI/API 조회·GUI 편집 → 내보내기가 이어진다. OS별 릴리스 작업은 내장 UI와 API 스모크 검증을 통과해야 한다. Linux 실행 파일은 Node·Rust·셸 없는 컨테이너에서도 CLI·내장 UI/API가 작동해야 하며, npm tarball은 Node만 있는 컨테이너에서 오프라인 설치·실행되어야 한다. 실제 다른 PC에서 공개 설치·화면·공동 편집 확인은 게시 후 수행한다.

검증 탐색: `install_001`, `INSTALL-001`, `scripts/install`, `scripts/release`.
