# UX-001 · 사용자 경험 행동 계약

구현 비종속: 특정 컴포넌트·레이아웃·저장 방식·식별자 규칙을 확정하지 않는다. 각 항목이 커지면 별도 UX ID로 분리한다.

| 계약          | 기준                                                                                     |
| ------------- | ---------------------------------------------------------------------------------------- |
| 무학습 사용   | LTM 사용법·문법·전문 지식을 AI에게 가르치지 않고 자연어로 요청한다.                      |
| 한눈에 파악   | 목적·상태·핵심 쟁점·결과물을 빠르게 이해한다.                                            |
| 점진 공개     | 전체 정보는 언제든 확인, 기본은 필요한 것부터, 근거는 요청 시 확장. 초안(수신자가 받는 그대로의 글)도 기본은 접혀 있고 요청 시 펼친다.                      |
| 한 번에 시작 | 처음 화면에서 할 일을 적으면 그 내용이 담긴 요청 문장을 바로 건네받아, AI가 과업을 되묻지 않고 시작한다. 비워 두어도 시작할 수 있다. 목적을 적으면 세부 조건을 더할 수 있게 열린다. |
| 쉬운 말       | 사용자 화면에 나오는 모든 문장은 해당 분야 지식 없이 읽히는 일상어로 쓴다. 약어·내부 용어·파일 경로·명령어는 쓰지 않는다. |
| 한 줄 한 뜻   | 항목·질문·선택지는 짧은 한 문장 한 뜻("~를 ~하게 한다")으로 끝낸다. 풀이·조건은 제목 아래 '자세히'로 두어 궁금할 때만 펼치고, 수신자에게 가는 최종 지시서에는 함께 들어간다. 자세히는 '설명'(`- 일상어`)과 '기술'(`- [전문 지식]`) 두 칸이다. 개발·전문 분야 용어와 약어는 기술 칸이나 `[ ]` 안에만 둔다(제목·설명에는 쓰지 않는다). 칸이 비어도 화면에는 '없음'으로 남겨 빠진 곳이 보인다. 화면에서 제목은 가장 진하게, 자세히는 흐리게 보인다. |
| 큰 그림 먼저  | 각 단계와 갈림길은 먼저 "이걸 정하면 무엇이 달라지는지"를 한 문장으로 보여 주고, 기술적 근거·용어 설명은 요청 시 펼친다. |
| 판단은 결과로 | 사람에게 묻는 선택지는 결과·비용·되돌리기 쉬운지로 설명한다. 사람이 판단할 수 없는 기술 선택은 AI가 정하고 알리며, 사람이 바꿀 수 있다. |
| 행동 곁에 되돌리기 | 사람이 하는 행동(모두 좋아요·자세히 모두 보기 등 일괄 행동)은 그 행동이 일어나는 항목 목록 바로 곁에 두고, 되돌리기도 같은 자리에서 할 수 있다. 일괄 행동도 한 번에 되돌려진다. |
| 최소 질문     | 도구가 채울 일을 되묻지 않고 중요한 선택·충돌·위험만 묻는다.                             |
| 전문성        | 분야 관행·원칙을 선제 고려하며, 사용자 키워드 언급을 전제로 삼지 않는다.                 |
| 자동 구성     | 확정된 목적·범위·제약·결정·검수 기준을 일관된 지시서로 조합한다.                         |
| 기억과 참조   | 결정·변경·이력을 별도 지시 없이 관리하고 간결한 참조(예: PRTT-02, 형식 미정)로 이어간다. |
| 맥락 절제     | 과업에 필요한 내용만 AI에 전달하고 무관한 기록·프로젝트 정보는 넣지 않는다.              |
| 공동 편집     | AI 수정과 직접 수정이 같은 결과물에 반영되고 변경 내용을 이해할 수 있다.                 |
| 비차단 이동 | 어느 단계·지시서·노트로든 언제나 이동할 수 있다. 모달·잠금·되돌아갈 수 없는 흐름이 없다. 정한 갈림길도 다시 펼쳐 바꿀 수 있다. |
| 결과 독립 열람 | 최종 지시서는 진행 단계와 상관없이 항상 보이고 복사할 수 있다. 미완성이면 "초안"으로 표시한다. 펼치기 전에도 전달 단계의 복사로 가져갈 수 있다. 전달 단계는 복사 버튼 곁에 복사될 내용의 첫 줄들을 줄 단위로 잘라 미리 보여 주고, 확인 전 줄을 표시하며, 남은 줄 수를 알린다. 터미널 명령도 눌러서 복사한다. 펼친 초안이 길어도 복사·접기 막대는 화면 위에 붙어 따라온다. |
| 권고와 막힘 | 막힘(갈림길·빈 필수 단계)만 경고색을 쓴다. 확인 전 항목은 작성자와 관계없이 권고라 차분하게 표시하고 전달을 막지 않는다. 전달 단계에서 확인 전 항목은 단계별로 접어 두고, 펼치면 그 자리에서 확인·고치기를 하며 단계로 가기는 보조로 둔다. 확인한 묶음은 그 방문 동안 '확인함'으로 남는다. |
| 갈림길 의존 | 앞 갈림길의 선택에 따라서만 의미 있는 갈림길은 그 조건이 맞을 때만 묻는다. 조건이 맞지 않으면 그 자리에 흐리게·잠금으로 남겨 "'앞 질문'에서 '선택'을 고르면 정해요"를 보이고, 고를 수 없으며 막힘으로 세지 않는다. 앞 선택을 바꿔 조건이 깨지면 그 갈림길이 넣은 문장은 빠지고, 다시 맞으면 이전 선택이 돌아온다. 다른 갈림길을 잠그거나 여는 선택지는 고르기 전에 그 영향(잠기는·열리는 질문, 빠지는 답)을 보이고, 고른 뒤에는 그 자리에 무엇이 바뀌었는지와 되돌리기를 한 줄로 알린다. 되돌릴 수 있는 변경이라 확인 창으로 막지 않는다. |
| AI에게 묻기 | 항목·갈림길마다 그 자리에서 AI에게 묻거나 고쳐 달라는 한 줄을 남긴다. 요청은 대화가 아니라 지시서에 쌓이고, 그 자리에 '보냄'으로 보이며 지울 수 있다. 쌓인 요청은 한 번에 보내도록 AI에게 할 말 한 줄을 복사해 준다. 적어 두기만 하면 AI에게 닿지 않고, 전달은 사람이 붙여 넣어야 끝난다. 그래서 '① 복사 → ② AI 창에 붙여 넣기' 두 걸음을 화면 아래에 늘 떠 있게 보이고, 복사 전 요청이 있는 동안 복사 단추가 천천히 숨 쉬며 부르고 몇 개 남았는지 보인다. 복사하면 멈추고 ② 걸음이 밝아져 붙여 넣으라고 알린다. LTM은 보냈는지 알 수 없으므로 '보냄'이 아니라 '복사함'으로 말한다(이 브라우저의 편의 기록). 복사했지만 AI가 아직 맡지 않은 요청은 '붙여 넣으면 AI가 맡아요 · 기다리는 N개'로, AI가 맡으면 'AI가 처리 중 · 남은 N개'로 보이고, 모두 답하면 막대가 물러난다. 처리 중에 새 요청을 적으면 '복사 전'이 다시 함께 보인다. 요청 하나는 작은 대화 흔적으로 보인다: 내 말(나) 아래로 흔적 선이 이어지고, 처리 중이면 AI 자리에 깜빡이는 점이, 답하면 AI 말이 다른 모양(색 배경·AI 배지)으로 붙는다. 흔적 선의 칸(적어 둠 → 처리 중 → 답함)이 어디까지 왔는지 보인다. 지우기는 답 전까지, 답 뒤에는 확인(선택)과 닫기가 있다. 확인은 재촉하지 않는다: 확인 전이라도 경고·숫자로 부르지 않고, 확인하면 흔적이 흐려지며 한 줄로 접힌다. AI가 처리하면 그 자리에 답이 보이고 닫을 수 있다. 새로 남긴 요청·새로 온 답은 그 자리가 잠시 숨 쉬듯 밝아지고 모아 보내기 띠의 개수가 튀어 올라, 어디가 새로 켜졌는지 보인다(움직임 줄이기 설정이면 색으로만). 요청을 남기면 포커스는 연 버튼으로 돌아가고 화면은 움직이지 않는다. 화면 전체가 궁금하면 사진을 찍어 AI에게 보내도 된다고 안내한다. LTM 안에 대화창을 만들지 않는다(VISION-002). |
| 시각 단서 | 상태는 모양·색·글자로 함께 표시해, 글을 읽지 않아도 알아볼 수 있다(모서리 표식: ? 정할 것, ! 비어 있음, 숫자 확인 전, ✓ 완료). 단계마다 무엇을 정하는지 보여 주는 도트 상징이 있고, 막힘은 꺼짐·확인 전은 반쯤·완료는 제 색으로 켜져 진행이 게임 칸처럼 보인다. |
| 피로 없는 학습 | 반복해서 드러난 판단 기준은 AI가 취향 노트에 쌓는다. 사용자는 확인하거나 내려놓기만 한다(MEM-001). |
| 모션 품질 | 부드럽게 움직이되 프레임을 떨어뜨리지 않는다. 전환은 transform·opacity만 쓰고, 바뀌지 않은 데이터로는 다시 그리지 않으며, 동작 줄이기 설정을 따른다. |
| 전역·개별 조작 | 단계 전체 조작(모두 좋아요·자세히 모두·되돌리기)은 목록 바로 위 한 줄에 상태와 함께 모은다. 항목 조작(자세히·좋아요·고치기·빼기)은 모든 줄에서 같은 자리·같은 순서다. 개별 좋아요는 확인 전 항목마다 항상 있다. 반복되는 조작은 아이콘으로 줄이되 서로 모양이 겹치지 않게 하고(좋아요는 하트: 누르기 전엔 흐린 빈 하트라 이미 누른 것처럼 보이지 않고, 누르면 그 자리에서 차오르며 튄다. 좋아요·빼기는 결과를 알리고 바로 되돌릴 길을 준다) 이름은 툴팁·스크린리더로 준다. 주된 일괄 행동(모두 좋아요)만 글자를 함께 쓴다. |
| 펼치기·접기 | '자세히'를 하나 또는 모두 펼치고 접을 때 내용이 갑자기 나타나거나 사라지지 않는다. 들어올 땐 살짝 떠오르며 나타나고, 나갈 땐 흐려지며 빠진다. 접힘은 흐려짐과 아래 줄이 올라오는 것이 한 박자에 함께 일어난다. 모두 펼치기는 위에서부터 짧게 차례로 나타난다(전체 0.3초 이내). 밀리거나 당겨지는 아래 줄은 뚝 튀지 않고 새 자리로 미끄러진다. 높이는 애니메이션하지 않고, 동작 줄이기면 즉시 바뀐다. 펼친 상태는 키보드로도 바꾼다. |
| 시각적 완성도 | 정보 위계·가독성·예측 가능한 상호작용·접근성·인지 부담 최소화.                           |

- 형식 관문: AI가 쓰는 사용자 화면 문장은 길이·기호·약어 규칙을 어기면 저장되지 않고 사유와 고치는 방법을 돌려받는다. 사람의 입력은 막지 않는다. 이해되는지는 형식이 아닌 사용성 확인으로 본다(VISION-003).
- 측정
  - 모션: 단계 이동 중 프레임 간격 p95 16.7ms 이하, 긴 작업(50ms 초과) 없음. 데스크톱 브라우저에서 rAF로 측정한다.
  - 대비: 텍스트는 두 테마 모두 4.5:1 이상.
  - 실패 가시성: 저장 실패·복사 실패를 성공처럼 보이지 않게 하고, 입력한 내용을 보존한다.
  - 나머지는 VISION-003의 평가 설계로 정한다.
