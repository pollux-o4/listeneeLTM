# MEM-001 · 취향 노트

사용자의 질의·요구 패턴에서 드러난 판단 기준을 프로젝트에 쌓아, 다음 작업자(AI·사람)가 같은 설명을 다시 듣지 않게 한다. 결정: ADR-0006, 구조: ADR-0008.

- 저장: `.ltm/preferences.json`(커밋 대상). 항목은 묶음(자유 문자열), 기준 한 문장, 근거(최근 8개), 출처 지시서(최근 8개), 상위 원칙, 작성자, 확인 여부, 내려놓음 여부로 이뤄진다.
- 구조(2단): 원칙 = 하위 기준을 가진 항목. 하위 기준은 같은 묶음의 활성 기준이며 원칙이 될 수 없다. 원칙의 근거 강도는 하위 기준 근거의 합이다.
- 쌓기: AI가 관찰해 `note`로 기록한다. 묶음과 기준 문장이 같으면 새 항목 대신 근거를 더한다(반복 관찰 = 강화). 사용자에게 채우라고 요구하지 않는다.
- 사람의 역할: 확인, 고치기, 내려놓기, 다시 적용. 내려놓은 항목은 지우지 않고 보존한다. AI가 같은 기준을 다시 관찰하면 근거만 쌓이고, 다시 적용은 사람만 한다.
- 읽기(맥락 절제): `ltm pref show`는 활성 항목만 묶음별로 출력하고 근거는 개수만 보여준다. 확인 전 항목에는 "(확인 전)"을 붙인다.
- 학습 루프(사람 참여·능동 학습)
  - 신호: 대화의 요청·지적과 함께, 사람이 GUI에서 남긴 행동(AI 추천과 다른 갈림길 선택, AI 항목 고치기·지우기, AI가 정한 갈림길 바꾸기)을 근거로 쓴다. 작성자 기록(DATA-001)으로 구분한다.
  - 적용 강도: 확인됨 = 기본값으로 따른다, 확인 전 = 약한 근거(추천 이유에만 반영), 내려놓음 = 따르지 않는다.
  - 능동 질문: 기준이 없거나 서로 충돌하고 선택이 되돌리기 어려우면 추측하지 않고 갈림길로 연다. 사람의 선택은 근거가 된다. 질문은 이 경우로 한정한다(UX-001 최소 질문).
  - 반대 신호: 노트를 따른 결과를 사람이 되돌리면 그 사실을 알리고, 반복되면 고치기·내려놓기를 제안한다. 내려놓은 기준을 다른 문장으로 바꿔 다시 기록하지 않는다.
  - 확인 요청: 새로 학습했거나 근거가 늘어난 확인 전 항목은 작업 끝에 한 줄로 알리고, 확인은 사람이 GUI에서 한다.
  - 우선순위: 현재 명시한 요청 > 확인된 노트 > 확인 전 노트 > 업계 관행. 일회성 예외는 노트를 바꾸지 않는다.
- 정리(무분별한 증가 방지)
  - 기록 전 활성 기준과 뜻을 비교해, 같으면 같은 문장으로 근거만 더한다.
  - 같은 묶음에 비슷한 기준이 3개 이상이면 원칙으로 묶기(`group`)를 제안한다. 풀기(`ungroup`)는 원칙을 내려놓고 하위 기준을 되돌린다.
  - 묶음 3~5개, 묶음당 최상위 항목 5개를 넘으면 합치기를 제안한다.
  - 확인 전이고 근거가 늘지 않은 채 지시서 5개가 지나면 내려놓기를 제안한다. 자동으로 지우지 않는다.
  - 프로젝트 파일에서 알 수 있는 사실은 취향이 아니므로 기록하지 않는다.
- 금지: 원문 인용, 개인정보, 일회성 지시.
- 실패: 빈 문장과 없는 id는 거부하고, 아무것도 바뀌지 않는다.
