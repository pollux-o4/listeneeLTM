# VISION-002 · 제품 형태·역할 분담·핵심 능력

## 형태

- 프로젝트에 설정하는 라이브러리(Vite처럼) + 독립 프론트엔드 UI(Storybook처럼).
- 주 진입점은 사용자가 이미 쓰는 AI 호스트(AI CLI·Claude Desktop·ChatGPT Desktop 등). 전용 챗봇·중앙 대시보드는 만들지 않는다.
- 도구는 자기 역할(불완전한 요청 → 더 나은 지시서)만 알고, 설치된 프로젝트의 분야는 실행 시 해석한다. 프로젝트 간 맥락은 분리한다.

## 역할 분담

- AI: 작업 수행 주체이자 기본 조작자.
- LTM: 구조화된 작업 공간 + 품질 보조 엔진.
- GUI: 채팅 복제가 아닌, AI와 사람이 함께 편집하는 구조화 화면.

## 사용 흐름

1. 한 번 설치·연결 → AI 호스트가 LTM 기능을 발견.
2. 평소처럼 자연어 요청.
3. AI가 LTM 호출, 허용된 프로젝트 맥락 파악.
4. GUI에 초안 반영, 중요 선택·미결정 노출.
5. GUI 직접 편집 또는 AI 수정 지시 → 같은 데이터.
6. 검수·저장, 이후 작업에 재사용.

## 핵심 능력

| 능력               | 해결 문제                   | 방향 예                           |
| ------------------ | --------------------------- | --------------------------------- |
| AI 발견·호출       | 사용법을 AI에게 설명해야 함 | 호스트에 기능·입출력·조건 등록    |
| 프로젝트 맥락 적응 | 프로젝트마다 다름           | 허용 자료에서 파악·격리           |
| 의도 이해          | 요청 받아쓰기에 그침        | 목적·기대 결과·제약·불확실성 구분 |
| 누락·가능성 발견   | 모르는 것은 묻지도 못함     | 사례·원칙·기준 능동 탐색          |
| 의사결정 지원      | 질문이 사용자에게 전가      | 합리적 기본값, 중요한 선택만 확인 |
| 구조화·정합성      | 실행하기 어려움             | 범위·우선순위·충돌·완료 조건      |
| 공동 편집          | AI·GUI 결과 불일치          | 단일 상태, 변경·되돌리기          |
| 실행 가능한 결과물 | 긴 프롬프트만 남음          | 수신자별 지시서·검수 기준         |
| 연속성             | 반복 요구·이전 결과 훼손    | 결정 기록·버전 비교·영향 확인     |

## 전문 도메인 지식

휴리스틱·원칙·표준·검증 관행을 과업에 맞춰 찾아오는 것은 누락 발견 수단이다. 사용자가 언급하지 않아도 적절하면 고려하되(예: 개발 과업의 SOLID), 기계적 적용으로 과업을 무겁게 만들지 않는다.

## 결과물 성질

목적 명확성·범위 명확성·실행 가능성·판단 근거·검증 가능성·연속성·적절한 복잡도. 출력 종류 예: 초기 기획 지시서, 기능 수정 요청서, 조사 브리프, 납품 전 검수 지시서.
