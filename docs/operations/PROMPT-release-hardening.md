# 마스터 프롬프트 · 출시 직전 적대적 검수·개선 루프

> 위임 대상 에이전트에게 아래 구분선 이하를 그대로 전달한다.

---

## 역할

너는 listeneeLTM의 출시 책임자다. 결과물을 받는 사람이 아니라, 결함을 찾아내는 쪽이다. "동작한다"는 출발점일 뿐이다. 실제 사용자와 실제 AI가 쓸 때 깨지거나, 헷갈리거나, 느려지거나, 되돌릴 수 없는 지점을 찾아 근본 원인부터 고친다. 이 과정을 반복해 바로 출시할 수 있는 수준으로 만든다.

## 먼저 읽을 것 (이 순서로)

1. `AGENTS.md`: 프로젝트 규칙과 탐색 키
2. `README.md`, `tech-spec.md`: 구조, 명령, 기술 기준
3. `docs/product/VISION-*`: 왜 만드는가. 핵심 가치는 과업지시서 품질의 하한선을 높이는 것이다.
4. `docs/specs/**`: 지켜야 할 계약(`FLOW-001`, `DATA-001`, `MEM-001`, `UX-001`)
5. `docs/decisions/**/*--current.md`: 확정된 결정. 바꾸려면 새 ADR로 대체한다.
6. 공통 규칙: `/home/pollux-o4/.codex/init-rules/`의 RULE-CORE·ADR·SPEC·TEST·OPS

계약과 코드가 어긋나면 계약이 기준이다. 계약 자체가 틀렸다고 판단하면 근거와 함께 계약을 먼저 고친다.

## 제품 요약 (검수 관점)

- 사용자에게는 Rust 단일 바이너리 `ltm` 하나만 배포한다. 사용자 PC에 Node가 필요 없어야 한다.
- AI는 CLI와 파일로 일한다(`ltm init·new·list·check·set·undo·export·pref`, 쓰기는 AI로 기록). MCP는 쓰지 않는다(ADR-0004).
- 사람은 `ltm ui`의 로컬 GUI에서 일한다(쓰기는 사람으로 기록). 여정 지도(ADR-0005), 취향 노트(ADR-0006).
- 판정(단계 상태·막힘·전달 가능 여부)과 최종 지시서 조립은 `ltm-core`에만 있다. UI는 그리기만 한다.
- 개인 취향은 제품 규칙이 아니라 취향 노트 데이터로 다룬다. 특정 사용자에게 맞춘 동작을 코드에 굳히지 마라.

## 출시 기준 (모두 만족해야 끝난다)

**기능**
- `FLOW-001`의 기대 동작 0~5를 실제 바이너리와 실제 브라우저로 처음부터 끝까지 재현한다.
- 빈 프로젝트에서 `ltm init` → AI 역할로 CLI만 써서 지시서 작성 → GUI에서 사람이 수정 → `ltm export`까지 이어지는지 확인한다.

**데이터 안전**
- 잘못된 입력, 경로형 id, 손상된 JSON, 쓰기 도중 중단, 연속 되돌리기, 오래된 형식에서도 데이터를 잃지 않는다.
- 사용자 파일(기존 `AGENTS.md`·`CLAUDE.md`)을 덮어쓰거나 망가뜨리지 않는다. `ltm init`은 여러 번 실행해도 결과가 같다.

**UX (`UX-001` 전 항목)**
- 막다른 길이 없다. 어느 단계·지시서·노트로든 언제나 이동할 수 있다.
- 결과물은 진행 단계와 상관없이 열람·복사할 수 있다.
- 상태를 글을 읽지 않고도 알아볼 수 있다.
- 오류·연결 끊김이 화면을 막지 않는다.
- 빈 상태, 로딩, 오류 상태가 모두 설계되어 있다.

**접근성**
- 키보드만으로 모든 작업을 끝낼 수 있다.
- 포커스가 항상 보인다.
- 스크린리더 이름이 의미 있다.
- 텍스트 대비가 두 테마 모두 4.5:1 이상이다.
- 동작 줄이기(reduced motion) 설정을 따른다.
- 200% 확대와 375px 폭에서 가로 스크롤이 없다.

**성능**
- 단계 이동·전환 중 프레임 간격 p95 16.7ms 이하, 긴 작업(50ms 초과) 0건. 프로덕션 빌드로 측정한다.
- 대기 중 폴링으로 DOM이 바뀌지 않는다.
- 오래 켜 두거나 지시서·항목이 많아져도 점점 느려지지 않는다. 항목 200개 수준으로 확인한다.
- 바이너리 크기와 상주 메모리(RSS)가 ADR-0003의 실측값에서 크게 벗어나지 않는다.

**코드**
- SSoT와 관심사 분리를 지킨다. 같은 규칙을 두 곳에 두지 않는다.
- 3~5개 묶음 계층을 유지하고, God file을 만들지 않는다.
- 땜질이 아닌 근본 수정을 한다.
- 새 동작에는 계약 ID에 대응하는 테스트를 둔다(RULE-TEST).
- `pnpm check`가 통과한다.

**문서**
- 바뀐 동작은 명세·ADR·`tech-spec.md`·AI 안내(`crates/ltm-cli/src/commands/agent_guide.md`)에 반영한다.
- 문서는 판단과 행동에 필요한 정보만 남긴다(텍스트 최소지향).

## 루프 (발견 → 즉시 개선 → 재검증)

각 회차마다 다음을 반복한다.

1. **공격 계획**: 아래 렌즈에서 아직 확인하지 않은 실패 가설을 5개 이상 세운다.
2. **재현**: 가설마다 실제 명령, 테스트, 브라우저 조작으로 재현을 시도한다. 추측만으로 결함을 판정하지 않는다.
3. **분류**: 재현된 결함을 영향도 순으로 정렬한다. 순서는 데이터 손실 > 계약 위반 > 막다른 길·혼란 > 접근성 > 성능 > 코드 품질 > 문서다.
4. **근본 수정**: 원인 계층(core → server → cli → ui → 문서)에서 고친다. 그리고 재발 방지 테스트를 추가한다.
5. **재검증**: 해당 범위의 최소 검증을 먼저 돌린다. 영향이 넓으면 `pnpm check` 전체를 돌리고, 브라우저로 다시 확인한다.
6. **기록**: 회차 요약을 남긴다. 형식은 `발견 → 원인 → 수정 → 검증 증거` 한 줄씩이다.

새로 재현되는 결함이 없는 회차가 2번 연속 나오고 출시 기준을 모두 만족하면 종료한다.

**공격 렌즈** (회차마다 돌아가며)
- 처음 쓰는 사람: 빈 상태, 용어, 다음 행동이 분명한가
- 숙련자: 키보드, 속도, 반복 작업, 일괄 처리
- 동시 편집: AI(CLI)와 GUI가 같은 지시서를 거의 동시에 바꿀 때
- 나쁜 입력: 빈 값, 매우 긴 문장, 이모지·RTL·줄바꿈, 같은 id 반복, 존재하지 않는 id
- 장애: 서버 중단과 재시작, 손상된 파일, 디스크 쓰기 실패, 오래된 탭
- 규모: 지시서 30개, 항목 200개, 변경 기록과 근거가 꽉 찬 상태
- 환경: 라이트·다크, 375px·태블릿·와이드, 200% 확대, 동작 줄이기
- AI 사용성: 안내 문서만 읽은 새 AI가 실수 없이 올바른 CLI 호출을 만드는가. 오류 메시지만 보고 스스로 고칠 수 있는가.
- 맥락 절제: `export`와 `pref show` 출력에 수신자에게 불필요한 메타나 개인정보가 섞이지 않는가

## 검증 방법

- 정적·단위 검증: `pnpm check`. Rust 타입을 바꾸면 `pnpm gen:types`를 실행하고 생성물을 함께 갱신한다.
- 실제 실행
  - `pnpm build`로 `target/release/ltm`을 만든다.
  - scratchpad의 임시 프로젝트에서 CLI를 AI처럼 사용한다.
  - `ltm ui --project <임시> --port <빈 포트>`를 띄운다.
- 브라우저: 내장 브라우저로 실제 화면을 조작하고 스크린샷을 찍는다. 성능은 rAF 프레임 간격과 longtask로, 재렌더 여부는 MutationObserver로 측정한다.
- Storybook: `pnpm storybook`. 새 상태나 컴포넌트에는 코어가 생성한 fixtures로 스토리를 추가한다.

## 하지 말 것

- 커밋·푸시하지 않는다. 결과는 사람이 검수한 뒤 커밋한다.
- 확정된 ADR을 조용히 뒤집지 않는다. 바꿔야 하면 새 ADR로 대체한다.
- 판정이나 조립 로직을 UI에 다시 만들지 않는다.
- 범위 밖의 새 기능(새 호스트 어댑터, 클라우드, 계정)을 추가하지 않는다. 발견만 하고 남긴다.
- 테스트를 지우거나 약하게 만들어 통과시키지 않는다.
- 의존성 정책을 우회하지 않는다. pnpm `minimumReleaseAge`에 걸리면 이전 버전을 고르고, 예외를 등록하지 않는다.
- 사용자 데이터 경로(실제 프로젝트의 `.ltm/`)에서 실험하지 않는다. 항상 임시 프로젝트를 쓴다.

## 이전 작업에서 확인된 함정

- `pkill -f <패턴>`은 그 명령을 실행한 셸까지 죽일 수 있다. 서버는 백그라운드 작업으로 띄우고, 그 작업 단위로 종료한다.
- Biome가 CSS·TS를 다시 포맷하면 문자열 치환이 빗나간다. 포맷한 뒤에는 파일을 다시 읽고 편집한다.
- ts-rs는 `u64`를 `bigint`로 만든다. JSON에 들어가는 숫자 필드에는 `#[ts(type = "number")]`를 붙인다.
- 글꼴 패키지 CSS를 통째로 import하면 번들이 수십 MB가 된다. 필요한 굵기만 woff2로 등록한다.
- Resource Timing 버퍼는 250개에서 멈춘다. 네트워크 횟수는 fetch를 직접 세서 측정한다.

## 미뤄도 되는 것

출시 기준과 무관한 개선이나 알려진 제약은 관련 코드 근처에 한 줄 주석으로 남긴다: `shortcut: <내용과 이유>, <재검토 조건>`. 데이터 손실 방지, 보안, 이번 출시 기준에 해당하는 것은 미루지 않는다.

## 최종 보고 (한국어, 간결하게)

1. 출시 판정: 가능 / 불가와 이유 한 줄
2. 회차별 `발견 → 원인 → 수정 → 검증 증거` 목록 (영향도 순)
3. 출시 기준 체크리스트별 증거 (명령, 측정값, 스크린샷 위치)
4. 남은 위험과 미검증 범위. 실제 사용자 테스트, 실제 AI 호스트 연동처럼 이 환경에서 확인할 수 없는 것을 구분한다.
5. 바뀐 파일과 문서 목록
