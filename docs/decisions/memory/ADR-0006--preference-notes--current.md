# ADR-0006 · 개인 취향은 제품 원칙이 아니라 취향 노트 데이터로

- 맥락
  - 첫 사용자(작성자)의 대화 패턴을 분석하면 뚜렷한 판단 기준이 보인다. 예: 자명한 결정은 알아서, 흐름에 갇히지 않기, 결과물을 따로 보기, 부드럽지만 빠른 모션.
  - 이를 제품 UI에 그대로 굳히면 다른 사용자에게 맞지 않는다(좁은 프레이밍).
  - 반대로 매번 다시 설명하게 하면 기억과 참조 계약(UX-001)을 어긴다.
- 대안
  - 첫 사용자 취향을 제품 기본값으로 고정한다.
  - 설정 화면에서 사용자가 직접 입력하게 한다.
  - AI가 관찰해 쌓고 사람은 확인만 하는 프로젝트 기억(취향 노트)을 둔다.
- 선택: 취향 노트(MEM-001).
  - 제품 UI는 어떤 사용자에게도 통하는 원칙(UX-001)으로 구성한다.
  - 개인의 판단 기준은 근거와 함께 데이터로 쌓고, AI가 작업 전에 읽는다.
  - 예: 갈림길을 AI가 직접 정할지 사용자에게 열어 둘지는 노트의 `결정` 기준을 따른다.
- 이유
  - 쓸수록 다음 작업자가 맥락을 쉽게 이해한다. 사용자는 입력 부담 없이 확인만 한다.
  - 기준을 바꾸려면 노트만 고치면 된다. 코드를 바꿀 필요가 없다.
- 결과
  - AI 안내 문서(`ltm init`이 설치)에 노트를 읽고 쓰는 절차가 포함된다.
  - 프로젝트 간 공유(사용자 전역 노트)는 하지 않는다. 프로젝트 간 맥락 분리 원칙 때문이며, 필요해지면 별도 ADR로 다룬다.
