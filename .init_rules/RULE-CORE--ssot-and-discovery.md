# RULE-CORE · SSoT와 경로 탐색

- 식별
  - 폴더: 문서 종류·관심사. 파일명: 고정 ID·키워드·상태.
  - 원본 ID는 프로젝트 내 유일하며 폐기 후에도 예약한다.
  - 파일 하나는 질문·책임·작업 하나를 맡는다.
- 계층화
  - 코드·파일·폴더·문서·UI는 관심사별로 묶고, 각 수준의 주요 묶음은 3~5개를 목표로 한다.
  - 상위는 역할을 요약하고 세부는 하위로 내린다. 평면 나열이 커지면 책임·변경 이유로 분리한다.
  - 계층마다 명확한 이름과 역할을 부여하고, 함께 이해·변경하는 요소는 가까이 둔다.
- 원본
  - 구현 값: 코드·심볼. 계약: 명세. 선택 이유: ADR.
  - 프로젝트에는 구체적 결과물·추가 규칙을 두고 공통 규칙은 RULE ID로 참조한다.
- 탐색
  - 경로 우선 탐색, ID 토큰 전체 일치.
  - 목차는 관심사·탐색 키만 유지한다.
- 관계
  - 종류+고정 ID로 단방향 기록: `대체: ADR-0042`, `검증: SAVE-001`.
  - 역관계는 ID 검색으로 찾고 외부 근거는 출처 URL을 보존한다.
